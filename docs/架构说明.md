## 二、分层职责

### 2.1 前端层（frontend/）
- **App.vue**：编排器。5引擎快捷卡、SSE 事件分发（token/tool_start/tool_result/interrupt/done）、会话切换。
- **MessageItem.vue**：消息气泡。工具卡片（执行中/完成状态、参数/结果折叠）、thinking 提示、流式 ▋ 光标。工具名中文映射（paper_search→文献检索 等）。
- **MarkdownRenderer.vue**：markdown-it 渲染 + highlight.js 代码高亮 + GFM 表格 + **DOI 链接高亮样式**（`a[href*="doi.org"]`）。
- **api/**：`http.js`（fetch + JWT + 401 触发重登录）、`chat.js`（SSE `_processStream` 事件解析）、`auth.js`、`history.js`。

### 2.2 后端层（src/api_view/）
- **web_main.py**：FastAPI 主应用。lifespan 后台惰性初始化 Agent（登录/健康检查不阻塞）。
- **api/chat.py**：SSE 流式核心。`stream_chat_response` 用 `agent.astream(stream_mode=["messages","values"], subgraphs=True)`，输出事件：token/tool_start/tool_args/tool_result/tool_end/interrupt/done/error。`emit_research_report` 的 markdown 参数增量投影为 token（报告流式进入助手气泡）。
- **api/auth_routes.py + auth.py**：JWT 登录 + RBAC（admin/researcher/student/viewer）+ 密码多格式校验（bcrypt/sha256/明文）。
- **api/history.py**：会话列表/消息/删除/重命名，按用户隔离。
- **agent_loader.py**：Agent 单例 + 会话归属 + 展示消息存取（local_session_store JSON 持久化）。

### 2.3 Agent 层（src/agent/）
- **main_agent.py**：`create_deep_agent` 组装。工具池 = 学术 MCP 工具 + web_search + write_markdown_table + emit_research_report + save_report_locally + get_system_date。子 Agent = literature-analyst（②③深度）/ review-expert（⑤）。
- **memory/prompts.py**：系统提示词。五大引擎分流 + 零幻觉铁律 + 千人千面 + 出表规范。
- **middlewares/**：ContextInjection（注入用户/分流提示）、MemoryUpdate（自动记忆研究方向）、Summarization（历史压缩）、EnsureToolCallPairs（修补悬空 tool_calls）。
- **subagents/**：YAML 配置 + loader（工具名子串匹配解析）。

### 2.4 学术数据层（src/mcp_server/）
- **server_main.py**：fastmcp streamable_http，注册 6 个学术工具。
- **tools/unified.py**：统一 Paper 数据类 + HTTP 客户端（429 重试退避）+ 内存缓存 + OpenAlex 倒排索引→摘要重建。
- **tools/crossref_tools.py**：CrossRef（主 DOI 源，`paper_search` + `paper_by_doi`）。
- **tools/openalex_tools.py**：OpenAlex（`paper_search` + `topic_trend` + `author_profile` 含 h 指数）。
- **tools/semantic_scholar_tools.py**：S2（`paper_search` 纯文本摘要 + `cross_search` 交叉检索）。
- **tools/academic.py**：引擎编排层，多源归并去重 + 降级（`paper_search` 等）。

## 三、零幻觉溯源机制（核心壁垒）

1. **唯一事实源**：所有文献/作者/DOI 必须来自工具召回，系统提示词硬约束「禁止编造」。
2. **DOI 强制**：`Paper` 模型每条都带 `doi_url`，工具返回的 `suggested_markdown` 含可点 DOI 链接。
3. **多源归并**：CrossRef（DOI 权威）+ OpenAlex（富数据）+ S2（摘要）三源去重，保留最全信息。
4. **空结果如实**：工具未召回时，Agent 如实说明「未找到」（实测：OpenAlex 未收录 Jason Wei 时，Agent 诚实说明并用 paper_search 反向构建）。
5. **报告校验**：`emit_research_report` 校验长度/标题，防半截报告。

## 四、与参考工程（采购助手）的差异

| 维度 | 采购助手 | MyResearcher |
|---|---|---|
| 数据域 | Java ERP 物料/订单 | CrossRef/OpenAlex 学术文献 |
| 模型 | deepseek-v4-pro/flash | 同（已验证当前可用） |
| 沙箱 | opensandbox（代码执行） | **去掉**（无需） |
| 数据库 | 可选 MongoDB | **去掉，仅 SQLite** |
| MCP 工具 | erp-api + analysis 两服务 | **单服务 academic-api** |
| 报告 | emit_procurement_report | emit_research_report |
| 子 Agent | procurement-analyst/order | literature-analyst/review-expert |
| 前端 persona | 采购智能助手 | MyResearcher 科研导师 |

## 五、关键设计决策

1. **去 opensandbox**：研途场景不需要代码执行，去掉减少依赖与启动时间。
2. **去 MongoDB**：SQLite checkpoint + JSON 会话存储足以支撑 MVP 多会话记忆，进程重启可保留。
3. **CrossRef 为主 DOI 源**：全球 DOI 注册机构，返回的 DOI 最权威可信，最贴合「DOI 溯源」主张。
4. **千人千面轻量实现**：用户偏好 Store 存「认知等级」+「研究方向」，MemoryUpdateMiddleware 自动维护，提示词据此调节晦涩度——轻量实现 PPT 的「伴随式成长」。
5. **报告流式投影**：`emit_research_report` 的 markdown 参数通过 `EmitMarkdownStreamer` 增量投影为 token，让完整报告流式进入助手气泡，避免工具卡片与正文重复。
